# Data

**No data files are stored in this repository.** The `data/` folders exist so that scripts have somewhere to read from and write to on your machine, but everything inside them is ignored by Git. This file records where the data actually lives.

> **Fill in the bracketed sections below when you set up your project, and update the Archived section when the study closes.** This file is the only durable link between the code in this repository and the data it was run on. If it is out of date, the project stops being reproducible.

---

## Why data is not in the repository

Three reasons, in order of how badly they bite:

1. **Git history is permanent.** A file you commit today and delete tomorrow is still in the repository's history. If the repository is ever made public — which is the goal for most projects at publication — every file ever committed becomes public too. For research involving young people, schools, or districts, that is not a recoverable mistake.
2. **Access is controlled elsewhere, deliberately.** Data access is granted person by person on Google Drive. A repository shared with a collaborator is not the same as a data access decision, and the two should not be able to drift apart.
3. **Git is bad at large files.** GitHub refuses anything over 100 MB and warns above 50 MB. Version control is designed for text, where it can show you what changed line by line; a 400 MB `.sav` file just makes the repository slow for everyone forever.

## Folder structure

```
data/
├── raw/         Exactly as received. Read-only. Never edit these files.
└── processed/   Generated by code/01_clean.R. Safe to delete and regenerate.
```

### `raw/` is read-only

Download it, and then leave it alone. Do not open it in Excel and fix a typo. Do not delete a bad row. Do not re-save it in a different format. Every correction, recode, and exclusion belongs in `code/01_clean.R`, where it is visible, documented, and reversible.

### `processed/` is disposable

Anything here should be regenerable by running `code/run_all.R`. If you have a processed file that cannot be recreated from raw data plus code, something is missing from the code.

## If you need to commit a data file anyway

Occasionally it is genuinely useful to track one small, **fully de-identified** analytic file — it makes results reproducible for a reviewer without any data request. That is a reasonable thing to do, deliberately, for one file:

```bash
git add -f data/processed/analysis_sample.csv
```

Before you do, confirm all of the following:

- [ ] No names, emails, phone numbers, addresses, or student/district IDs
- [ ] No free-text responses (people identify themselves in open text constantly)
- [ ] No dates of birth, and no combination of variables that could re-identify a small subgroup — a single participant in one school, one grade, one demographic category is identifiable even without a name
- [ ] Under a few MB
- [ ] Permitted by the IRB protocol and any data use agreement
- [ ] You have said out loud that this file may become public, and that is fine

If you are unsure about any line above, ask before committing. Uncommitting is much harder than not committing.
